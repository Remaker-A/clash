# Baby Camera / 桌面宠物「Links」

---

## 一、项目做了什么

**一句话**：把一台**云台摄像头硬件**养成一个有形象、有声音、能听懂话、会用动作回应的**桌面数字宠物**，最终命名为 **Links**。

起点是"婴儿/宠物摄像头"（Camera Baby），随着追踪和云台越调越顺，目标转向了更高层的东西：**让摄像头"活起来"** —— 有视觉形象、有语音、有动作语言，构成完整的交互人格。

### 演进脉络

| 阶段 | 目标 |
|---|---|
| **1. 追踪与云台** | 把目标追踪 + 云台运动调稳（"整体调得不错了"） |
| **2. 形象设计** | 重新设计桌面宠物形象（按用户上传图抠图） |
| **3. 语音链路** | STT 识别 → LLM 理解 → TTS 输出 |
| **4. 动作语言** | 摇头、点头、眨眼（用呼吸灯做表情） |
| **5. 多模态协同** ⭐ | 语音 + 视觉 + 云台动作**联动**成一体 |
| **6. 唤醒机制** | 连续喊两遍 "Links" 激活 |

## 二、用了什么技术

### 2.1 硬件

| 设备 | 说明 |
|---|---|
| **Link 2**（云台摄像头） | 主硬件，带云台（水平/俯仰）+ **呼吸灯** |
| 扬声器 / 麦克风 | 用于 TTS 输出与语音输入 |

### 2.2 语音链路

| 环节 | 技术 |
|---|---|
| **STT**（语音识别） | 多轮换模型调优（"识别不是很准，换一个模型"） |
| **LLM**（理解与决策） | 接入 OpenAI 兼容接口（`base_url` + api_key），做"智慧/自主决策" |
| **TTS**（语音合成） | 反复调语速、语调、音高 |

### 2.3 视觉

- **摄像头视觉识别**：本体摄像头（曾误用电脑自带摄像头，被用户逮到）
- **视觉模型**：用于动作/姿态识别
- **抠图**：形象素材处理（"直接用原图抠下来，现在还有一点点白边"）

### 2.4 开发方式 ⭐

用户**大量使用多 Sub Agent 并行开发**加速：

> 「开几个 sub Agent，用几个 GPT-5.5 来加速开发」

这是这个项目一个很鲜明的工程特征 —— 复杂改造时开多个 GPT-5.5 subagent 并行推进不同模块。

## 三、具体是怎么设计的

### 3.1 唤醒与交互协议

```
1. 连续呼叫两遍 "Links" → 激活唤醒
2. 唤醒后进行语音交互 / 发布语音指令
   （例如：让它摇摇头、点头）
```

### 3.2 三位一体的交互联动 ⭐

这是项目追求的核心 —— 用户明确要求把这些**联合起来一起做交互**：

| 通道 | 内容 |
|---|---|
| **TTS / STT** | 听说能力 |
| **桌面宠物形态** | 屏幕上的视觉形象变化 |
| **云台动作** | 物理摇头、点头、转向 |

**目标**：不是三个独立功能，而是**同一意图下的同步表达** —— 比如宠物说"好呀"的同时点头 + 云台轻微摆动 + 形象做表情。

**遇到的反复**：用户多次指出「语音交互和动作控制还是没有协同起来」「基本上还是不会说话就那几个姿势识别的声音」，这块是**最难啃的部分**，需要反复检查云台控制、语音理解、LLM 回复后的语音输出三条链路。

### 3.3 拟人化设计

| 维度 | 设计要求 |
|---|---|
| **声音** | 不要机械感，不要"故意拖慢语速"的感觉 |
| **语速** | 逐步调快（"快一点"反复出现） |
| **音高** | 用户吐槽"有股东北碴子味儿，可能是缺乏音高的变化" → 需要加音高变化 |
| **形象** | 按用户上传图抠图，注意去白边 |
| **动作** | 加入更多动作（不只有摇头点头） |

### 3.4 呼吸灯做表情

一个有意思的硬件级巧思：

> 研究**用 Link 2 的呼吸灯来做眨眼或更多效果**

把 LED 灯效当作"眼神"来用，低成本增加拟人感。

### 3.5 语音延迟问题排查

用户反馈：「**我说完过了好久这个消息框才出现或者根本没出现**」

排查方向：STT 识别延迟 / Webhook 回调 / 消息推送链路。
（涉及"软件连接的接口 Webhook"—— 硬件与软件之间的通信机制。）

## 四、踩坑记录

| 问题 | 表现 |
|---|---|
| **云交互死板** | "一直在重复几句话，没有真正做到智慧或自主决策" → 接入新模型 |
| **协同失败** | 语音和动作控制各自能跑，但合不到一起 |
| **误用摄像头** | Agent 用了电脑自带摄像头而非硬件设备 |
| **抠图毛边** | 形象有白边，需要抠得更仔细 |
| **形象太丑** | 第一版设计被否，改用原图抠图 |
| **语音延迟** | 说完很久无响应 |

## 六、复盘

1. **多模态协同是真正的难点** —— 单独做好 STT、TTS、云台控制不难，难的是让它们在同一意图下**同步表达**。这个项目 80% 的返工都在这。
2. **拟人感是细节堆出来的** —— 语速、音高变化、抠图白边、呼吸灯节奏，任何一个不到位都会立刻"露馅"。
3. **多 Sub Agent 并行是硬件项目的加速器** —— 在链路复杂时开多个 GPT-5.5 subagent 分头推进，比串行快得多。
