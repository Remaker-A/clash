# WorldGen 世界生成

> 工作区：`D:\文档\Cursor\worldGen` ｜ 会话数：**46** ｜ 提问轮次：**155** ｜ 时间跨度：2026-03-16 ~ 2026-03-18
> 特点：**接入第三方 3D 世界生成 API**，密集调试接口与 3D 交互

---

## 一、项目做了什么

**一句话**：一个**节点式可视化平台**，接入 **World Labs 的 Marble** 世界生成 API，让用户从图像/视频素材生成可探索的 3D 世界，并支持在画布上以节点方式编排。

---

## 二、用了什么技术

### 2.1 核心外部能力：World Labs Marble API ⭐

| 项 | 内容 |
|---|---|
| 官方文档 | `https://docs.worldlabs.ai/api` |
| 能力 | **资产（图像 / 视频）上传 + 3D 世界生成** |
| 结果形态 | 生成后返回世界链接，如 `https://marble.worldlabs.ai/world/<id>` |

### 2.2 前端技术

| 能力 | 技术 |
|---|---|
| **全景图查看** | `PanoViewer` |
| **3D 高斯泼溅查看** | `SplatViewer` |
| **画布编排** | 节点式 Toolbar（可复用组件） |
| 交互控制 | 参照 Marble 的视角控制方式 |

## 三、具体是怎么设计的

### 3.1 节点式画布架构

画布上每个"世界"是一个节点，节点带 **Toolbar**，工具栏能力可跨节点类型复用（"参照正常的节点的 tool bar"）。

### 3.2 Viewer 交互控制升级 ⭐

**问题**：原有 `PanoViewer` / `SplatViewer` 的交互方式只有**缩放和拖动**，用户反馈「**视角调整起来比较困难**」。

**方案**：**参照 Marble 的交互控制方式**改进 —— 即对标业界最好的同类产品体验，而非自己发明一套。

> 这是一个很实用的产品策略：**在交互体验上直接对标标杆产品**，减少试错成本。

### 3.3 全屏查看功能

为新的全景图节点 Toolbar 添加**全屏查看**能力，并保持与其他节点 Toolbar 的一致实现。

### 3.4 资产上传与结果回传链路 ⭐

接口调试踩了几个坑，最终理清：

```
上传图像/视频资产
      ↓
调用生成 API
      ↓
获取结果
      ↓
返回世界链接 → 点击跳转 marble.worldlabs.ai/world/<uuid>
```

**关键发现**：直接返回的链接**无权限访问**（`You don't have permission to view this world`）—— 需要仔细研读官方 API 返回字段，才能拿到**可访问的正确链接**。

## 四、踩坑记录

| 问题 | 表现 | 解决 |
|---|---|---|
| **API Key 管理** | 需要换新 key 并删除旧 key | 更新配置 + 重启前端 |
| **生成结果无权限** | 返回的链接打开提示 `You don't have permission` | 重读官方文档，理清返回结构 |
| **生成框 Bug** | 点击空白区域生成框就消失，导致中断 | 修复事件处理 |
| **视角控制差** | 缩放+拖动的交互难以调整视角 | 对标 Marble 重构控制方式 |

## 六、复盘

1. **第三方 API 的坑常在"返回结构"而非"调用"** —— 能调通不代表能拿到可用的结果，权限链接这种细节必须读透文档。
2. **交互体验对标标杆产品** —— 与其自己设计一套视角控制，不如直接参照 Marble，省时且效果好。
3. **组件一致性** —— 新节点的 Toolbar 复用已有实现，保持一致体验。
