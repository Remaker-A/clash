## 一、项目做了什么

**一句话**：宠物**智能项圈** —— 硬件（项圈）+ 软件（APP/网页端）结合的宠物监护产品，核心是 **GPS 定位防丢 + 轨迹围栏 + 数字孪生宠物互动**。

### 功能模块

| 模块 | 内容 |
|---|---|
| **GPS 定位** | 实时位置、轨迹回放 |
| **自定义围栏** | 电子围栏 + 越界检测 |
| **场景化训练** | （方案阶段先不做具体实现） |
| **心理状态 / 应激指数** | （方案阶段先不做具体实现） |
| **数字孪生宠物** | 主人与宠物分开时，与数字孪生 AI 宠物互动 |
| 首页功能板块 | 多板块展示设计 |

## 二、用了什么技术

### 2.1 硬件

| 项 | 内容 |
|---|---|

### 2.2 软件

| 层 | 选型 |
|---|---|
| 前端 | **网页实现**（MVP 阶段 APP 先用网页代替） |
| 后端 | 独立后端服务 |
| GPS | **模拟数据**（随机游走 + 预设路线） |

### 2.3 MVP 阶段的取舍 ⭐

用户明确划定了 MVP 边界，这是很关键的决策：

> 「场景化训练模块和心理状态/应激指数**具体实现先不做**，APP **先用网页来实现**，GPS **用模拟的**」

即：**先用可控的模拟数据跑通全链路**，把硬件依赖和算法难点后置。这让 3 天内就能出完整闭环。

## 三、具体是怎么设计的

### 3.1 软硬件协作架构

```
宠物项圈（Tuya T5AI-CORE）
        ↓ 定位数据
   后端服务
        ↓
   网页端 APP
   ├── GPS 定位页面
   │    ├── 实时位置
   │    ├── 轨迹回放
   │    └── 自定义围栏
   ├── 首页（多板块）
   └── 数字孪生宠物互动
```

### 3.2 GPS 模拟器设计 ⭐

因为 MVP 阶段不接真实 GPS，设计了一个**内置模拟器**：

| 模式 | 说明 |
|---|---|
| **随机游走** | 模拟宠物无规律移动 |
| **预设路线** | 模拟固定遛弯路径 |
| **围栏检测** | 模拟越界场景，验证告警链路 |

> 这个设计的价值：**用模拟数据把前端和后端的完整链路都验证掉**，等真实硬件就绪时只需替换数据源。

### 3.3 轨迹与自定义围栏

在 GPS 定位页面上实现：
- **轨迹绘制**：记录并回放宠物移动路径
- **自定义围栏**：用户在地图上画多边形区域
- **越界检测**：位置出围栏时触发

### 3.4 数字孪生宠物 ⭐

这是一个有产品想法的设计：

> 「主人与宠物分开的时候，可以和这个**数字孪生的 AI 宠物**进行互动」

价值：
- 宠物不在身边时，用户仍能获得陪伴感
- 把"工具型"产品（防丢）变成"情感型"产品（陪伴）
- 增强用户粘性和打开频次
