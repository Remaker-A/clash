## 一、项目做了什么

**一句话**：用**摄像头识别人的运动频率**，让健身团课里的**多人运动节奏去驱动主伴奏音乐** —— 你动得快，音乐节奏就快。

### 核心创意 ⭐

> 「在健身房团课或团操的多人运动氛围下，用主伴奏音乐控制运动节奏。
> 在场景中，**每个人对应不同乐器**（鼓点、吉他、贝斯）。
> 每个人运动频率和乐器的演奏频率/速度是对应的 —— 你运动得快，那个乐器演奏的节奏就比较快。」

这是一个**把物理动作直接映射成音乐**的互动设计：

```
用户 A 的运动频率  →  鼓点节奏
用户 B 的运动频率  →  吉他/贝斯速度
        ...
        全部叠加  →  共同的伴奏氛围
```

## 二、用了什么技术

| 层 | 选型 |
|---|---|
| 视觉识别 | **摄像头 SDK**（用户提供了 SDK 文件）+ 动作频率识别 |
| 姿态识别 | 人体动作 / 姿态识别（可选用 RM u 等方式） |
| 音频 | 多轨乐器音轨 + 实时调速 |
| 开发环境 | 完整环境配置（用户要求"你直接帮我配环境"） |

### 开发顺序决策 ⭐

用户明确排了优先级：

> 「**我们先做视觉实现**」

即先把"能识别动作频率"这一最不确定的环节跑通，再去处理音频侧 —— **先攻克风险最高的部分**。

同时为了快速验证，先用**电脑自带摄像头**做动作识别实现（不阻塞在专用硬件上）。

## 三、具体是怎么设计的

### 3.1 系统流程

```
摄像头采集
    ↓
人体/动作识别（SDK）
    ↓
计算每个参与者的运动频率
    ↓
映射到各自的乐器轨
    ↓
实时调整乐器播放速度
    ↓
叠加成主伴奏音乐
```

## 五、复盘

1. **先攻最不确定的环节** —— 明确"先做视觉实现"，因为动作频率识别是最大风险点，音频侧相对确定。
2. **用电脑摄像头先跑通** —— 不阻塞在专用硬件上，快速验证核心可行性。
3. **跨模态映射的产品创意** —— "运动频率 → 乐器节奏"把健身和音乐两个场景自然缝合，是很好的产品想法。
