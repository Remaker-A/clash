## 一、项目做了什么

## 三、具体是怎么设计的

### 3.1 环境搭建顺序

```
1. 安装 Ubuntu 22.04 LTS
2. 检查是否已装 Conda / Miniconda
3. 安装 Miniconda → 创建虚拟环境（隔离依赖）
4. 安装 MuJoCo（机器人仿真）
5. SSH 远程连接（别名 amd）
6. 远程安装 openclaw
7. 安装 openWakeWord + pvrecorder（语音唤醒）
8. 配置 Codex CLI
```

**关键工程原则**：**用虚拟环境隔离依赖** —— 用户主动要求，避免污染系统 Python。

### 3.2 唤醒词链路设计 ⭐

用户的思路很清晰：

> 「既然 **openWakeWord** 已经能稳稳地"接头"，我们要做的就是把那声枯燥的"叮"换成更有温度的 **"Hey I'm there"**。
> 要把这套流程…」

设计含义：
- openWakeWord 负责**检测唤醒词**（已稳定可用）
- 检测到之后，原来是播放一声机械的"叮"
- 改为播放更自然、有温度的语音 **"Hey I'm there"**

> 这跟 Baby Camera 项目是同一个设计哲学：**工具要有人格**，反馈声音不该是冰冷的提示音。

### 3.3 安装步骤的严谨性

用户要求：

> 「计划先用**虚拟环境 + py3.11** 给我一个**完整的安装步骤**」

即先出**可复现的完整步骤文档**，再动手执行 —— 避免远程环境装乱。

1. **虚拟环境隔离是远程环境的生命线** —— 系统 Python 一旦污染，远程排查成本极高。
2. **先写步骤再执行** —— 面对陌生远程环境，先出可复现的完整步骤，能避免大量返工。
3. **反馈声音要有人格** —— 从"叮"到 "Hey I'm there"，是产品体验层面的用心。
