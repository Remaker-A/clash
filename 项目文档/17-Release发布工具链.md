# Release 工具链 —— 版本发布自动化

> 涵盖工作区：`release tool`（4 会话）、`new release`（11 会话）、`Tapnoz skill`（4 会话）、`CC`（2 会话）
> 时间跨度：2026-03-23 ~ 2026-04-08

---

## 一、项目做了什么

**一句话**：一套**自动收集 → 编写 → 发布**版本更新（release note）的工具链，含管理后台 + 产品站内展示。

### 子项目

| 子项目 | 内容 |
|---|---|
| **Release Tool** | 从 **Lark（飞书海外版）** 提测单自动收集信息 → 编写 release note → 发布 |
| **New Release** | 把 release note 接入产品网页，展示给终端用户 |
| **Tapnoz Skill** | 任务跟进类 Skill（轮询 GitHub PR 状态） |

## 二、Release Tool（发布管理后台）

### 2.1 数据来源 ⭐

> 「new release 的参考信息来源是 **Lark 的功能验收测试群聊中的提测单**（如图），
> 所以要求这个 tool 能够**接入 lark**（飞书海外版），然后自动去获取这些信息，
> 然后根据这些信息来编写…」

**设计链路**：

```
Lark 功能验收测试群聊
    ↓ 自动抓取提测单
信息聚合
    ↓ AI 编写
Release Note
    ↓ 人工确认
发布到产品网站 + 管理 Dashboard
```

### 2.2 技术选型

| 项 | 内容 |
|---|---|
| 集成 | **Lark（飞书海外版）** API |
| AI 编写 | 先用 **OpenAI** 测试 |
| 后台 | **Dashboard** 管理界面 |
| 登录/权限 | 设计时预留，**先不做**（明确的范围控制） |

### 2.3 范围控制

用户明确划界：

> 「需要从头创建一个，**本地开发先跑起来**，测试**先用 OpenAI**，需要**登录/权限管理但先不做**」

> MVP 思维：先跑通主链路，权限体系后置。

## 三、New Release（站内展示）

### 3.1 展示逻辑设计 ⭐

用户定义了一个有层次的展示交互：

> 「用户**首次进入** tapnow 页面时先显示 **campaign 的活动窗口**（图一），
> 但是当用户点击底部的**更新**（图二）后，**在更新结束后就不再显示 campaign，而是显示新版本的 new release**」

**逻辑**：

| 用户状态 | 展示内容 |
|---|---|
| 首次进入 | Campaign 活动窗口 |
| 点击"更新"并完成更新后 | **切换到** New Release 内容 |

> 设计意图：**用活动窗口拉新/促活，更新流程结束后顺势引导看新版本**。把两个营销触点自然衔接。

### 3.2 集成方式

已有一个 bot 能获取 release 信息源并编写 new release，本项目负责**接入产品 web 页面**，并把**用户确认后**的 release 信息发布到网页。

## 四、Tapnoz Skill（任务跟进）

### 4.1 功能

一个**跟进任务进展**的 Skill，核心是轮询 GitHub 等工作流的状态。

### 4.2 关键优化：轮询终止条件 ⭐

**问题**：

> 「当前的轮询会**持续到代码合并**，造成较多的**资源浪费**。
> 修改为**获取 Preview 的连接后就停止跟进**。」

**优化**：

| 原逻辑 | 新逻辑 |
|---|---|
| 轮询 → 直到代码合并 | 轮询 → **拿到 Preview 链接即停止** |

> 这是一个很实际的工程判断：**任务目标达成就该停**，不必追求流程走完。Preview 可用意味着"可以验收了"，后续的合并流程不需要本 Skill 盯着。

### 4.3 同步节奏优化

> 「调整进展**同步节奏**，降低原有的密集同步频率，**避免对相关人员造成干扰**，
> 优化后需确保 skill 能更高效地跟进任务且不影响信息传递的及时性。」

**平衡点**：既不能刷屏打扰，也不能漏掉关键信息。

- Tapnoz Skill（Preview 优先终止 + 同步节奏优化）

## 六、复盘

1. **自动化链路的"信息源头"决定成败** —— 从 Lark 提测单直接抓，比让人手写一遍再喂给 AI 高效得多。
2. **轮询要设"达标即停"** —— 追到 Preview 可用就够了，盯到合并纯属浪费。
3. **多个营销触点的衔接设计** —— Campaign 窗口与 New Release 的切换，把两个触点串成一条用户路径。
4. **MVP 要敢划边界** —— 权限体系明确"先不做"，把资源集中在主链路。
