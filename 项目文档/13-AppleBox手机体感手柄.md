# Apple Box —— iPhone 当赛车游戏体感手柄

> 工作区：`D:\文档\Cursor\apple box` ｜ 会话数：**6** ｜ 提问轮次：**40** ｜ 时间跨度：2026-06-18 ~ 2026-06-23

---

## 一、项目做了什么

**一句话**：把 **iPhone 变成赛车游戏的体感方向盘** —— 用手机陀螺仪控制《神力科莎（Assetto Corsa）》里的赛车转向和油门。

用户给出了一句非常准确的架构判断：

> 「**正确架构不是"iPhone 直接变成 Xbox 手柄"**，而是：
> iPhone 读取陀螺仪 / 姿态数据 → 通过 Wi-Fi 发给 Windows → Windows 程序把数据转换成**虚拟 Xbox 手柄输入** → 赛车游戏读取这个虚拟手柄。」

---

## 二、用了什么技术

| 层 | 选型 |
|---|---|
| **传感器端** | iPhone 陀螺仪 / 姿态数据 |
| **传输** | **Wi-Fi** —— **HTTPS / WSS**（WebSocket Secure）服务 |
| **转换端** | Windows 程序 → 虚拟 Xbox 手柄输入 |
| **目标游戏** | 《神力科莎 AC》（Assetto Corsa） |

**关键洞察**：游戏只认 Xbox 手柄输入，所以必须做一层**虚拟手柄驱动**，而不是让游戏直接读手机。

---

## 三、具体是怎么设计的

### 3.1 数据流架构 ⭐

```
iPhone（陀螺仪 / 姿态）
        ↓ Wi-Fi (HTTPS / WSS)
Windows 服务端
  ├── 接收姿态数据
  ├── 转换为虚拟 Xbox 手柄输入
  └── 输出到系统手柄层
        ↓
《神力科莎 AC》读取虚拟手柄
```

### 3.2 真正的难点：并发控制不中断 ⭐

真机联调后的核心问题：

> 「现在确实能实现一些很基础的操控了，但是**在转向的同时去控制油门的开度会出现控制中断**，
> 然后是**线性转向做的也不是很流畅**，
> 很多操控会被意外打断，**尤其是刹车油门和转向**。」

拆解出的技术问题：

| 问题 | 表现 | 技术根源 |
|---|---|---|
| **控制中断** | 转向 + 油门同时操作时中断 | 单通道串行处理，多轴输入互相阻塞 |
| **转向不线性** | 线性转向不流畅 | 姿态数据到转向量的映射曲线问题 |
| **意外打断** | 刹车/油门/转向互相干扰 | 多路输入未做独立通道与优先级 |

> 本质是**多轴并发输入**的问题：手柄的多个轴（转向 X 轴、油门 Y 轴、刹车 Z 轴）必须能**独立、同时**更新，不能串行等待。

### 3.3 单机部署简化

为了让 iPhone 能访问 Windows，做了 HTTPS/WSS 服务配置，目标是让 Windows 端服务处于**可被 iPhone 访问**的状态，并输出**最短步骤清单**（iPhone 侧 + 游戏侧各要做什么）。

## 六、复盘

1. **架构判断先行** —— 用户一开始就纠正了"iPhone 直连 Xbox"的错误架构，明确中间必须有一层虚拟手柄。**架构对了，后面才有意义。**
2. **体感控制的核心是多轴并发** —— 转向、油门、刹车必须独立通道同时更新，任何串行处理都会造成"打断"。
3. **映射曲线决定手感** —— 陀螺仪姿态到转向量的非线性映射，是"流畅度"的关键。
