# Agent Company（多 Agent 协作公司模拟）

> 特点：**用 Skill 体系驱动多 Agent 协作**，是 Skill 工程化最早的实践场

---

## 一、项目做了什么

**一句话**：一个**模拟公司运作的多 Agent 系统** —— 让多个 AI Agent 像公司团队一样分工协作，并通过 **Skill 体系**给它们注入专业能力。

这个项目最突出的贡献不是"公司模拟"本身，而是**把 Skill 作为核心工程单元来使用**：

| Skill | 作用 |
|---|---|
| **Code Review Skill** | 对整个项目做完整、全覆盖的代码审查 |
| **Changelog / Release Note Skill** | 每天自动生成用户友好型的版本变更日志 |

---

## 二、用了什么技术

### 2.1 Skill 工程体系 ⭐

深度使用 **`skill-creator`** 来创建、评判、迭代 Skill：

| 用法 | 说明 |
|---|---|
| **创建 Skill** | 用 skill-creator 创建 code review、changelog 等 skill |
| **方案对比** | "可以先深度思考然后从多个方向来规划，最后选定一个最佳方案后再开始创建" —— 采用方案 C |
| **Skill 评判** | "用 skill-creator 评判这两个 skill 哪个好 / 分别跑一个测试" —— **让 Skill 之间互相 PK** |

> 这是一种很成熟的做法：**不只创建 Skill，还要能评估和择优**。

### 2.2 Release 平台集成

| 项 | 内容 |
|---|---|
| 平台 | `https://release.tapnow.top/admin/releases` |
| 权限 | 平台 key（含读写 + 发布权限） |
| 集成方式 | 让 bot 写完 changelog 后**自动发布** new release note |

### 2.3 前端

涉及 Agent 管理界面、任务栏等 UI（"重启前端"多次出现）。

## 三、具体是怎么设计的

### 3.1 Changelog 日报 Skill ⭐

**需求**：

> 「我需要这个 agent **每天**生成最新版本**用户友好型**的 changelog 日报，每天总结最新改动情况，**无新版本则可不关注**。」

拆解出的设计要点：

| 要点 | 设计 |
|---|---|
| 触发频率 | 每天 |
| 输入源 | 版本变更信息 |
| 输出风格 | **用户友好型**（不是技术 commit log） |
| 空版本处理 | 无新版本则不关注（**避免噪音**） |
| 创建方法 | skill-creator，先多方向探索再定方案 |

### 3.2 自动发布到 Release 平台 ⭐

用户提出的问题很有代表性：

> 「我要让 bot 在写完 changelog 能够在这个 release 平台上**自动发布** new release note 要怎么搞？**直接改 skill 还是我把这个平台的 key 甩给你？**」

最终确定的设计：

| 决策点 | 选择 |
|---|---|
| 版本号 | **默认自动递增** |
| 发布流程 | **创建后先存草稿 → 让用户确认 → 再发布**（人工卡点） |
| 数据结构 | 每个 changelog 条目作为**一个 feature** |

> **关键设计**：自动生成 + **人工确认后再发布** —— 既享受自动化效率，又在对外发布这种不可逆动作上保留人工卡点。这是很成熟的自动化设计思路。

### 3.3 Code Review Skill

| 步骤 | 动作 |
|---|---|
| 1 | 用 skill-creator 创建 code review skill |
| 2 | 对整个项目做**完整、全覆盖**的 code review |
| 3 | **先修复第一批**（分批推进，不一次性全改） |
| 4 | 用 skill-creator **评判两个 skill 哪个好**，分别跑测试 |

## 六、复盘

1. **Skill 不只是"提示词包"，是可评估、可择优的工程单元** —— 用 skill-creator 创建 + 评判 + PK，形成了完整闭环。
2. **自动化要有不可逆动作的人工卡点** —— 生成可以全自动，但"发布"必须人工确认后执行。
3. **先多方向探索再选型** —— "深度思考 → 多方向规划 → 选定最佳 → 再开始创建"，比直接开写方案质量高得多。
